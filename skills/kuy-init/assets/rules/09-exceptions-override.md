# Exceptions & Override Process

These rules are the project's agreed standard and the user may edit them at any time. A change that cannot follow a rule:

1. Name the rule and the reason it cannot be followed.
2. Propose the exception to the user (or in the pull request) and wait for approval.
3. Mark the code with a comment that states the exception and a follow-up (`TODO(<ticket>): remove exception to <rule>`).
4. Schedule the follow-up that removes it.

Temporary hacks without an approved exception are not allowed. When rules conflict, the more specific rule wins; the user's explicit instruction wins over both.
